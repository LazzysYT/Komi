## Исправленные баги

1. При переносе архива использовался один `onConflict: user_id,anime_id` для
   всех таблиц. Но у папок ключ `(user_id,name)`, а у содержимого папки
   `(user_id,folder_name,anime_id)`. Теперь у каждой таблицы правильный ключ,
   `ignoreDuplicates:true` не затирает облачные данные.
2. Списки, избранное, прогресс и папки могли обрезаться из-за лимита строк
   Supabase. Теперь все пять коллекций загружаются стабильными страницами
   по 500 строк; тест включает 1 205 записей и сетевой сбой после первой страницы.
3. Локальный аккаунт без подтверждённого Supabase Auth больше не получает
   ложное сообщение об успешном сохранении избранного.
4. Импорт статусов/избранного/прогресса/папок охраняется проверкой владельца
   и уникальных ключей; при смене аккаунта импорт прекращается.

## Не пройдено / не следует считать готовым

- **Настоящий вход двух email/Google аккаунтов в двух браузерах**:
  GitHub Actions `auth-isolation-e2e.cjs` запускается только вручную
  с актуальными test-account secrets. Это не то же самое, что SQL-симуляция.
- Полный Google OAuth и подтверждение почты в Preview.
- Синхронизация Watch Party между двумя настоящими браузерами и плеерами.
- Завершающее отключение публичного доступа к `public.animes` и
  `public.online_users` — RLS там пока OFF, критическое предупреждение осталось.
- Монетизация/платежи и разрешения на источник серий не проверены.

## Безопасный порядок релиза

1. Проверить **успех GitHub Actions именно на последнем commit SHA**.
2. Провести реальный E2E с двумя отдельными тестовыми аккаунтами,
   включая обычные пользовательские списки, Watch Party, регистрацию, выход.
3. Подтвердить наличие резервной копии и плана rollback в Vercel.
4. Выпустить проверенный клиент и перепроверить live-домен.
5. Только затем выполнить ручной `supabase/manual-release/phase1-restrict.sql`
   и проверить, что старые публичные UPDATE/INSERT закрыты.
6. Проверить Supabase Security Advisor и ручной сценарий гостя/двух аккаунтов.
7. На ошибке не восстанавливать анонимную запись автоматически;
   использовать заранее подготовленный безопасный rollback-план.

Ни одна операция QA в этом отчёте не удаляла или переписывала
пользовательские записи или содержимое каталога.
