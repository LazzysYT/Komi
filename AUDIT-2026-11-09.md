# Reliability audit — 2026-11-09

Baseline: GitHub main 8567609. The original Komi-main directory is an older archive and was left unchanged.

## Implemented

- Shared source parser accepts HTTPS/protocol-relative sources, decodes legacy iframe entities once, rejects credentials and unsafe protocols, and classifies media by URL pathname.
- Native video and HLS share lifecycle/event ownership. HLS.js 1.6.19 loads only for browsers lacking native HLS. Closing/replacing media destroys the old loader.
- Progress saves every 10 seconds and on pause, seek, end and close, with ordered/coalesced requests. Save errors are visible. Per-element episode/account identity prevents stale events writing to another episode/account. Unknown/live duration becomes finite zero.
- Closing preserves position; source changes preserve duration. Pending detail requests cannot reopen a dismissed modal. Newer in-session progress survives an older server read.
- Watch Party uses the same parser/HLS adapter, compensates sampling latency, coalesces writes, publishes fresh position on heartbeat, and invalidates cancelled creation. External embeds still synchronize only episode/source.
- Favorite writes are awaited and duplicate clicks are blocked. Queued AniCoin requests retain their original account owner.
- Admin search cancels superseded requests, has a timeout, checks the current query, and renders provider text through DOM textContent.
- Player title/folder markup is escaped. Static forms have shared inline validation. Browser preference saves no longer rewrite the public legacy status blob.
- CI now tests the checked-out revision, root JS changes, deterministic regressions, two simulated party clients, and actual catalogue completion rather than accepting a loading message.

## Database

Inspected security/performance/health advisors, table columns, privileges, bot status counts and recent error summaries. Applied server migration `protect_legacy_backup_and_remove_unused_table_privileges`: enabled RLS and revoked public/anon/authenticated access to `animes_backup_20261105`; revoked TRUNCATE/REFERENCES/TRIGGER from visitor roles on `animes` and `online_users`. No records were deleted. Verification confirmed backup RLS enabled, both visitor reads denied and tested excess privileges denied.

At inspection: 4,970 synced, 1,785 no_match, 6 failed catalogue records. The observed failures included HTTP 400 on short YummyAnime search titles. These counts describe the old running bot, not the results of the proposed bot patch.

## Still open

- `animes` and `online_users` still have legacy public CRUD access without RLS. A coordinated owner-scoped social/presence migration is required; simply revoking access breaks remaining legacy callers. Backup isolation does not resolve this separate issue.
- Seven foreign keys lack covering indexes. No performance claim is made for them; measure workload before adding indexes.
- Real two-account auth, RLS, friends, profile/avatar persistence, AniCoin and Watch Party E2E have not run without dedicated disposable account credentials.
- Exact play/pause/seek synchronization inside arbitrary third-party iframes requires each provider's documented API. No such guarantee is made.
- HLS integration has syntax/lifecycle coverage, but a permitted live HLS stream was not played end-to-end. Network loss/browser shutdown may lose the final progress request; this patch does not add durable offline delivery.
- Existing legacy native alerts, CSS duplication and some modal accessibility behaviors remain outside the changed workflows. DESIGN.md records observed conventions, not a completed redesign.
