**Источник:** read-only SQL по production Supabase `public.anime_catalog`.
**Данные не менялись в ходе диагностики.**

## Фактические показатели

| Метрика | Количество |
|---|---:|
| Всего записей | 7 470 |
| `sync_status = 'synced'`, с данными серий | 5 680 |
| `sync_status = 'no_match'`, без доступных данных серий | 1 790 |

**Важно:** отсутствие записанных серий и статус `no_match` не доказывают,
что эпизоды уже вышли или доступны у лицензированного источника.
Не добавлять вымышленные ссылки, не подменять работающие источники пустыми.
Отсутствие сохранённого баннера не означает, что клиентская картинка не
отобразится: UI может запрашивать внешние иллюстрации.

## Проверочный запрос (read-only)

```sql
select coalesce(sync_status,'(null)') as status,
       count(*) as total,
       count(*) filter (
         where not (data ? 'episodes')
            or jsonb_typeof(data->'episodes') <> 'array'
            or jsonb_array_length(data->'episodes') = 0
       ) as without_episodes
from public.anime_catalog
group by coalesce(sync_status,'(null)')
order by total desc;
```

## Критерий завершения

Для каждой ранее проблемной записи известна проверенная причина;
реально доступные данные обновлены без потери старых; не создаются
вымышленные серии/источники; контрольные тесты каталога и плеера проходят.


## Найденный вероятный блокирующий фактор (исторические файлы)

В пользовательской библиотеке доступны прежние версии
`bot_fixed(1).js` и `bot_updated(1).js` от 05.11.2026.
В `bot_fixed(1).js` выборка на повторную синхронизацию **не включает**
`no_match`, а `BOT_LIMIT` ограничен значением 5. Эта версия также
не повторно проверяет `synced` для появления новых серий.

**Если именно эта версия всё ещё запускается,** она не будет повторно
обрабатывать 1 790 элементов `no_match` и не будет проверять вышедшие
эпизоды у уже синхронизированных аниме. Это обоснованная гипотеза,
но не подтверждение того, что текущий сервер использует данный файл.

Следующие безопасные исправления, после подтверждения работающей версии:
- Ввести лимит **до 200** за запуск с контролем задержек и ошибок API.
- Распределять задания между старыми `no_match` и `synced` по
  `last_sync_at`, чтобы не было голодания одной группы.
- Всегда сохранять старые эпизоды при отсутствии новых данных; не писать
  `synced` без подтверждения наличия серий.
- Запускать тестовый режим на небольшом наборе и отдельно проверить
  ответственность за секреты и запуск каждые 10 минут, не зависящий от ПК.
- Хранить актуальный запускаемый бот в GitHub (без секретов), с CI,
  тестами слияния эпизодов и журналом обработанных/пропущенных записей.


## Ограничение лицензирования источника

Официальная документация API YummyAnime (`https://api.yani.tv/`) прямо
указывает, что API предназначен для личного использования и требует
отдельного обращения для коммерческого применения. Поскольку Komi Anime
Hub планирует платную подписку и рекламу, **нельзя считать коммерческое
использование этого API разрешённым** без согласования с правообладателем
и проверки прав на размещаемые видео. Автоматически запускать старый
бот с этим источником на коммерческой площадке нельзя.

До разрешения можно проверять состояние уже сохранённого каталога,
улучшать скорость и исправлять UI, но не обещать работоспособность
неподтверждённых плееров и не подменять доступные легальные источники.
